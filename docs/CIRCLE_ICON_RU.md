# Иконка уведомлений в шторке (CircleIcon)

Цветной кружок слева в карточке уведомления Android 14+/16 SystemUI рисует из
`<application android:icon>` установленного пакета. Программно заменить его
нельзя (проверено на API 36.1): `setLargeIcon` уходит вправо, MessagingStyle-
аватар без conversation-shortcut рисуется внутри тела, переключение
launcher-псевдонимов меняет только ярлык. Единственный «нативный» способ —
conversation-уведомления, но они меняют семантику и вёрстку. Поэтому смена
кружка реализована переустановкой варианта APK, отличающегося ТОЛЬКО иконкой
манифеста.

## Как это работает

1. **Варианты** генерирует `scripts/make_circle_variants.py` из готового
   подписанного APK: патчит бинарный `AndroidManifest.xml` (атрибуты
   `icon`/`roundIcon`/`logo` у `<application>`; псевдонимы не трогаются — их
   иконки остаются своими), затем `zipalign` и `apksigner` ключом из
   `keystore.parallel.properties`. Пересборка gradle не нужна: все mipmap уже
   в APK, меняются 4 байта на атрибут. Один вариант — секунды.
2. **Настройка**: «Внешний вид → Иконка уведомлений»
   (`main.circle_icon`, `CircleIconPickerDialog`). Текущий вариант определяется
   по факту — `applicationInfo.icon` → `CircleIcon.currentVariant`, настройка
   ничего не хранит.
3. **Поиск ассета**: `CircleIcon.resolve` сначала проверяет релиз установленной
   версии (`ProPDA-<ver>-circle-<id>.apk`; для вшитого `pixel_4` — базовый
   `ProPDA-<ver>.apk`), а если варианта там нет — идёт по тегам из
   `releases.atom`, от самого свежего, рассматривая ТОЛЬКО релизы новее
   установленного (Android запрещает установку APK с меньшим versionCode).
   Поэтому варианты можно выкладывать не в каждый релиз; когда найденный
   вариант из более нового релиза, `Resolved.isUpgrade = true` и UI сначала
   спрашивает — смена иконки заодно обновит приложение.
4. **Установка**: `CircleIcon.download` качает найденный ассет и открывает
   системный установщик через FileProvider (`REQUEST_INSTALL_PACKAGES`;
   разрешение «неизвестные источники» установщик запрашивает сам). Данные
   сохраняются.
5. **Обновления**: `AppUpdateRepository.preferCircleVariant` ставит первым
   ассет с текущей иконкой, чтобы апдейт не возвращал стандартную; наличие
   ассета проверяется HEAD-запросом, базовая ссылка — запасная.

## Важные факты

- **SystemUI кэширует иконку пакета до перезагрузки**: иконка меняется только
  после ребута устройства (в диалоге об этом сказано). Ярлык лончера, сплэш и
  «Иконка приложения» не затрагиваются.
- Иконка в системных «Настройки → Приложения» тоже сменится — это тот же
  `ApplicationInfo.icon`.
- `CircleIcon.BAKED_ID` («pixel_4») держать синхронно с
  `<application android:icon>` в манифесте.

## Релизный процесс

После сборки релизного APK и ДО `gh release upload`:

```bash
python3 scripts/make_circle_variants.py --apk <путь к ProPDA-X.Y.Z.apk> --upload vX.Y.Z
```

`--upload` сам вызывает `gh release upload --clobber` (без него варианты просто
складываются в `circle-variants/` — можно залить вручную).

и загрузить в релиз ВСЕ файлы из `circle-variants/` рядом с базовым APK.
Без этих ассетов пункт настроек покажет «в релизе нет вариантов иконки
уведомлений», а обновление у таких пользователей молча вернёт стандартную
иконку: `preferCircleVariant` проверяет вариант HEAD-запросом и при отсутствии
оставляет базовый APK (иначе кнопка «Скачать» вела бы на 404).

Вес: 15 вариантов по ~14.7 МБ ≈ 215 МБ на релиз (базовый APK — 16-й).
Можно выкладывать подмножество (`--variants four_orange,glass_4,puzzle`) или
вообще не в каждый релиз: `CircleIcon.resolve` подхватит вариант из более
свежего релиза, предупредив пользователя об обновлении. Вариант из релиза
СТАРШЕ установленной версии не годится — downgrade запрещён системой.

Чтобы не грузить сотни мегабайт со своего интернета, этим занимается GitHub:
`.github/workflows/icon-variants.yml` срабатывает САМ при публикации релиза
(и вручную: Actions → Icon variants → тег). Он ждёт появления базового APK в
релизе до 20 минут (его обычно догружают уже после публикации), скачивает,
патчит, подписывает и прикрепляет варианты обратно.

Условия работы: workflow должен лежать в ветке по умолчанию (GitHub читает
release-триггеры только оттуда) и нужны 4 секрета с ключом подписи — список в
шапке самого workflow. Без секретов прогон не падает, а завершается
предупреждением: релиз просто выходит без вариантов.

## E2E-тест на эмуляторе (debug)

1. Собрать `assembleStableDebug`, сгенерировать вариант(ы) патчером.
2. `python3 -m http.server 8123` в каталоге `circle-variants/`.
3. Переопределить базовый URL (debug-сборка):
   `adb shell am broadcast --include-stopped-packages -n <pkg>/forpdateam.ru.forpda.debuglab.NotifIconLabReceiver -e mode circle_base -e url http://10.0.2.2:8123/`
   (без `url` — сброс). Cleartext к `10.0.2.2` разрешён только в debug
   (`app/src/debug/res/xml/network_security_config.xml`).
4. Пройти пикер; после установки — перезагрузка эмулятора; тестовое уведомление:
   `-e mode big` тем же ресивером.
